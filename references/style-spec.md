# 月明公众号 HTML 风格规范

## 方向

风格名：科技编辑部·轻排版。目标不是把每段做成卡片，而是让视觉层级对应论证层级：白底承载长文，深炭黑负责标题与最终结论，品牌绿负责关键结果，浅灰绿负责解释。

## 结构

1. 开篇视觉锚点：默认只放绿色顶线、`MOONLIT / FIELD NOTES` 和细分隔线，不重复微信公众号原生标题。用户明确要求时才能启用旧版深色题头。
2. 导语：第一段 19px/粗体；正文 17px、1.95 行高，段间距 21px。
3. 章节：`SECTION 01` + 左侧绿色短线 + 23px 深色标题；不使用整块黑底。
4. 图片：宽度 100%，下方使用 `FIG.01 · 图意`；底边使用 2px 亮绿识别线。
5. 重点：普通加粗保持深炭黑；关键结果使用强调绿和虚线下划线；核心金句直接放大，不套卡片；解释使用浅灰绿引用框；全文最终结论才使用深色 verdict。
6. 署名：右对齐、小号次级文字。

## 内容模块

渲染器支持以下 Markdown 写法：

```markdown
普通的 **关键概念** 不改变颜色。

这一节最重要的是 ==可再次召回的组合能力==。

> [!KEY] Skill 决定它会做什么，记忆决定它是不是同一个伙伴。

> [!NOTE] Prompt 只属于这一轮对话；记忆、知识、Skill 与工作区共同构成可持续上下文。

> [!VERDICT] 伙伴负责连续性，工作区负责隔离。

> [!COMPARE] 临时会话 || 数字伙伴

> [!QUESTION] 如果可以长期培养一个数字伙伴，你希望它记住什么？
```

一篇文章最多使用 3 个重点模块，最多一个 `[!VERDICT]`。每个 H2 章节最多 2 处 `==关键结果==`。模块必须承载论证节点，不要用来装饰普通段落。

核心金句优先选“判断 + 原因/结果”的完整句，推荐 18–42 个汉字；口号、情绪句、重复小标题和离开上下文无法理解的半句话不能作为金句。

## 微信兼容

- 只使用元素内联 `style`。
- 禁止 `<style>`、`<script>`、外链 CSS、动画、绝对定位、复杂 Grid/Flex。
- 布局优先使用 `section`、`p`、`blockquote` 和简单 `table`。
- 正文图片在草稿创建前必须成为 `mmbiz.qpic.cn` 地址；封面必须使用上传所得 `media_id`，不能把图片 URL 当封面 ID。
- 源 Markdown 保持只读；预览 HTML、微信 HTML、草稿 JSON 和结果清单写入独立输出目录。
- 标准 Markdown 管道表格必须输出为真实 `<table>`，使用内联样式、固定布局和可换行单元格；遇到列数错误要停止渲染，不能把表格静默塞进正文段落。发布前逐一检查 HTML 中的表格数量，并在手机宽度预览截图中确认文字、边框和横向溢出。
